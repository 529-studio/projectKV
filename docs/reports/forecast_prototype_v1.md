## 2. Method

- Chronological split: 70% train / 30% test over distinct `bin_start_utc` timestamps. Rows are never shuffled.
- Cutoff: `2026-10-29T09:35:00Z` (first test bin); 403 train timestamps, 173 test timestamps.
- Training samples whose target lands at or after the cutoff are purged per horizon, so a future value cannot leak across the split.
- Horizons: 10, 20, 30 minutes. Targets must exist at the exact future bin for the same camera; missing targets and incomplete lag features are excluded, never imputed.
- Candidate: ridge regression with L2 penalty `lambda=1.0`, target mode `delta`, features `lag_5m`, `lag_10m`, `lag_15m`, `rolling_mean_15m`, `hour_of_day`, `day_of_week`.
- Persistence predicts the current saturation index; the historical median uses the training median of future targets by camera and target hour, then camera, then global.
- Calendar columns are validated against `bin_start_utc` in `Asia/Ho_Chi_Minh`; a mismatch fails the run instead of training on the wrong seasonality.
- Directional accuracy compares `sign(prediction - current)` with `sign(actual - current)` using epsilon `1e-12`. Persistence predicts a zero change, so it only receives credit for genuinely flat actuals.
- Predictions are floored at 0.0 because saturation index is non-negative.

## 6. Caveats

- The v1 feature store does not carry rain columns, so rain is not part of this model despite being listed as a possible signal in Issue #302.
- Ridge regression is linear in the supplied features. Non-linear temporal structure and rare congestion events may remain unexplained.
- A passing gate is necessary but not sufficient for serving: the internal endpoint still needs its own staleness guard and live verification.
- All models are scored on the same feature-complete test rows. The historical-median baseline may be fitted on more training rows because it does not need lag features; the ridge candidate and persistence do not.
