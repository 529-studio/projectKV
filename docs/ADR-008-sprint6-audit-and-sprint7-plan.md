## 1. Context & Retrospective Audit Reconciliation

### 1.1. Sprint 6 Completion & Empirical Verification
Sprint 6 delivered **100% of its planned backlog (5/5 tickets)** across 14 merged pull requests to `dev`, backed by 100% passing tests under the Go race detector (`make test-go`), Next.js client suite (`npm test`), OpenVINO inference tests (`make test-model`), and automated Gitleaks secret scanning in CI:
- **S6-T1 (Issue #221, PR #232)**: Implemented Non-Maximum Suppression (`nms_cpu` with $\text{IoU} \le 0.45, \text{conf} \ge 0.25$), aspect-preserving letterboxing (`(114, 114, 114)`), and upgraded OpenVINO FP16 resolution to $416 \times 416$ at 24.01 FPS.
- **S6-T2 (Issue #222, PR #233)**: Calibrated physical corridor capacities (15.0–50.0 PCU) across all 837 cameras in `cameras_enriched.json` and persisted learned peak capacities to SQLite (`camera_capacities`), eliminating false congestion on wide expressways.
- **S6-T3 (Issue #223, PR #236, #237, #238)**: Redesigned `CameraModal.tsx` tactile affordances, reserved bracket syntax `[...]` strictly for passive chips, implemented 15s module-persistent cooldown, added `middleware.SecretSanitizer` in Gin, and added Schmitt trigger hysteresis ($\Delta = 0.05$) to mitigate telematics jitter.
- **S6-T4 (Issue #224, PR #243)**: Integrated centralized Gitleaks secret scanning in GitHub Actions CI targeting `main` and `dev`.
- **S6-T5 (Issue #225, PR #241)**: Built the missing leaf notification subsystem (`internal/notify`), raw SQLite subscription store (`internal/subscription`), and 30-minute sliding window debouncer.

### 1.2. The Reality Check: Ground-Truth Data Provenance & Low F1-Score Root Cause
While S6-T1 successfully resolved anchor duplication and geometric stretching (Macro F1 increased by +18.9% from 0.206 to 0.245; false alarms on CLEAR dropped by 50.0%), Macro F1 remained far below the theoretical target of $\ge 0.70$.

An exhaustive empirical audit of `tools/eval/label_real_batch.py` (commit `a5e1b71`, lines 67–130) uncovered the critical root cause:
- **The 764 "ground-truth" frames were NOT manually labeled by humans looking at images.**
- Instead, they were generated by a **crude string-matching heuristic** based on camera names and timestamp windows:
  - If a camera name contained `"huỳnh tấn phát"`, `"tô ngọc vân"`, or `"kha vạn cân"` during a night rainstorm, the script automatically injected `traffic: HEAVY, flood: SHALLOW`.
  - If a camera was located on an expressway during midday, it was tagged `traffic: CLEAR`.
- **Consequence**: When OpenVINO inspected an empty road on Huỳnh Tấn Phát at 20:47 and correctly detected 0 vehicles $\rightarrow$ it predicted `CLEAR`. The benchmark graded this against the flawed label (`HEAVY`) and marked it as a False Negative. **The model was being graded against an erroneous answer key.**
- **Flood Recall (0%)**: Stock COCO YOLOv8n only detects 80 standard COCO classes (vehicles). Because it has no concept of standing water, it predictably outputs `flood: NONE` across all 764 frames, resulting in a 100% False Negative Rate for flood.

### 1.3. Strategic Feedback & Core Directives from the Dev Team
1. **Transition to Autonomous Computer Vision (Zero-VLM Vision)**: Forcing commuters to manually click `[Xác minh ngập nước]` shifts the burden of perception onto users. The system must autonomously scan the 50 arterial Hot Set cameras first, classify traffic saturation and flood conditions on-premise, render distinct colored markers (Green/Yellow/Red for traffic, Blue for flood) directly on the map, and expand towards all 800+ cameras without cloud VLM API calls in the app's future.
2. **Active Crowdsource Feedback Flywheel (Human-in-the-Loop)**: When commuters view camera snapshots, if the model misclassifies conditions, provide a tactile `[Báo cáo ngập tại đây]` affordance. Automatically archive authentic contested production snapshots directly to Cloudflare R2 (`warded-proofs/feedback/`) with `trust: unverified` metadata and anti-spam rate limiting to continuously harvest real ground truth.
3. **Rebuild Data Labeling Taxonomy**: Overcome the fatal flaws of naive string heuristics and whole-scene tags by introducing directional multi-lane schemas (`inbound`/`outbound`), traffic light pause states (`WAITING_RED_LIGHT`), and motorcycle wheel waterline occlusion metrics.
4. **Map Clutter Hygiene**: Filter out 125 offline cameras (`NOT_IMAGE`/`NO_SIGNAL` black dots) by default to eliminate frustrating 503 ghost modals.
5. **Operational Verification**: Complete live Telegram alert verification on staging (`homesrv` Stack 14).
6. **Future Commute Alerting**: Keep the 30-minute homebound commute alert feature in the design backlog until the Valhalla/OSRM routing infrastructure spike is established.

## 2. Architectural Decisions for Sprint 7

### Decision 1: Transition to Autonomous Arterial Vision (50 Hot Set Cameras First)
No cloud VLM calls will be made for traffic classification. Instead, we establish autonomous on-premise perception across the 50 arterial Hot Set cameras (Võ Văn Kiệt, Mai Chí Thọ, Điện Biên Phủ, Cộng Hòa, Trường Chinh, QL1):
- A background worker in `services/go-server/internal/hotset/scheduler.go` polls the 50 arterial cameras every 60s.
- Inferences are dispatched to local `cv-engine` running OpenVINO FP16 YOLOv8n on `dev-box`.
- Saturation Index ($SI$) is computed using corridor-specific capacities (S6-T2) and Schmitt trigger hysteresis (Lesson 33).
- Results are cached in an in-memory thread-safe store (`hotset.Store`) and exposed via `GET /api/v1/cameras/hotset/status`.
- Commuters viewing the map see dynamic colored markers without clicking individual cameras:
  - `SI < 0.30` (`CLEAR`): Emerald Green.
  - `0.30 <= SI < 0.60` (`MODERATE`): Amber Yellow.
  - `SI >= 0.60` (`HEAVY` / `CONGESTED`): Rose Red.

### Decision 2: Active Crowdsource Feedback Flywheel & Unverified R2 Archiving
Because outdoor computer vision models will inevitably encounter edge cases (night glare, rain spray, lens obstruction), we empower commuters to dispute model verdicts:
- In `CameraModal.tsx`, add a high-contrast tactile action button: `[Báo cáo ngập tại đây]` with a 30-second client-side cooldown.
- Backend implements pure leaf package `services/go-server/internal/feedback/` exposing `POST /api/v1/cameras/:id/report-flood`.
- Enforces IP-based rate limiting (1 submission per IP per camera per 5 minutes) returning HTTP 429 upon spam.
- Asynchronously pulls the current camera frame and pushes the snapshot + companion JSON metadata to Cloudflare R2 bucket:
  - Path: `warded-proofs/feedback/<YYYY-MM-DD>/<camera_id>_<timestamp>.jpg`
  - Metadata: `{"source": "user_reported", "trust": "unverified", "camera_id": "...", "timestamp": "...", "client_ip_hash": "..."}`.
- Prevents unverified crowd reports from contaminating verified datasets while building an authentic retraining corpus.

### Decision 3: Rebuilding the Data Labeling Taxonomy
The current scene-level schema (`traffic: CLEAR, flood: SHALLOW`) cannot represent dual-carriageway corridors where one direction is gridlocked while the opposite lane is completely empty, nor can it distinguish waiting at a 30-second red light from chronic congestion:
- Upgrade `tools/eval/label_schema.json` to Draft-07 multi-lane structure supporting directional segments (`inbound`, `outbound`) and `WAITING_RED_LIGHT` states.
- Incorporate physical motorcycle wheel waterline metrics for flood depth:
  - `DRY`
  - `WET_SURFACE` (specular reflection on wet asphalt; no standing water)
  - `TIRE_QUARTER_SUBMERGED` (puddle, 5–10cm)
  - `TIRE_HALF_SUBMERGED` (hazardous flood, 15–20cm)
  - `IMPASSABLE` (> 25cm)
- Upgrade `tools/eval/labeler.html` and build validation CLI `tools/eval/validate_labels.py`.

### Decision 4: Map Clutter Hygiene (Filtering 125 Offline Cameras by Default)
125 cameras in `cameras_enriched.json` are currently offline (`NOT_IMAGE`/`NO_SIGNAL`), appearing as black dots. Clicking them produces 503 ghost modals:
- In `apps/web/src/components/Map.tsx`, add an active client-side filter hiding offline cameras by default.
- Provide a subtle monochromatic filter toggle: `[Ẩn camera mất tín hiệu]` / `[Hiện camera mất tín hiệu]`.
- Preserves full metadata in `cameras_enriched.json` for operational recovery while immediately cleaning the user explorer.

### Decision 5: Rain-Triggered Automated Hot Set Flood Verification (Bridge to Zero-VLM)
Claude correctly noted that stock COCO YOLOv8n has 0% flood recall, meaning pure OpenVINO cannot detect floods today without training a dedicated segmentation model:
- To eliminate the manual clicking burden immediately while respecting quota limits (10 RPM / 300 RPD), Gemini VLM is retained strictly as a temporary bridge.
- Trigger is automated: When Open-Meteo detects active rainfall ($\ge 0.10\text{mm/h}$), the Go background worker automatically verifies the 10 known flood chokepoints at a conservative rate ($\le 2\text{ RPM}$).
- Automatically updates map markers to Blue badge `[NGẬP NƯỚC]` and dispatches Telegram alerts.

### Decision 6: Live Staging Telegram Verification (Stack 14 homesrv)
The notification subsystem (`internal/notify`, `internal/subscription`, sliding 30-min debouncer) was fully tested under unit tests in Sprint 6 (PR #241), but currently runs in simulation mode (`TELEGRAM_BOT_TOKEN=""`) on staging:
- Deploy dedicated staging bot token to Portainer Stack 14.
- Execute live end-to-end alert verification script `scripts/verify_staging_telegram.sh`.
- Validate zero emojis, bilingual formatting, and token sanitization in logs.

### Decision 7: Explicit Deferral of 30-Minute Commute Routing
Commute route monitoring (predicting route conditions 30 minutes before departure) requires Valhalla/OSRM routing infrastructure, OpenStreetMap PBF ingestion, and edge-weight overlays:
- As confirmed by the audit, zero routing infrastructure currently exists in `services/go-server/`.
- This feature is formally deferred to a dedicated routing infrastructure sprint (Sprint 8+).

## 4. Definition of Done & Operational Guardrails

All Sprint 7 pull requests must strictly comply with `AGENTS.md`:
1. **Rule 1**: Zero emojis across all UI components, notifications, logs, and commit messages. Minimalist, monochromatic styling. Codebase, documentation, and tooling 100% English. Bilingual `vi`/`en` for web UI.
2. **Rule 2**: Sound, root-cause solutions only. Never choose convenient hacks or shortcuts out of fear of complexity.
3. **Rule 3**: Explicit estimation provided before commencing work.
4. **Rule 4**: End-to-end bug reproduction and empirical verification prior to declaring fixes complete.
5. **Rule 5**: Zero direct push to `main` or `dev`. All work on feature branches (`feat/*`, `fix/*`, `docs/*`) with PRs targeting `dev`.
6. **Rule 6**: Holistic documentation synchronization across `docs/` and root `README.md` (both English and Vietnamese sections).
7. **Rule 7**: Hand-written SQL only (no ORM). Pure leaf-modulith architecture in `services/go-server/`.
8. **Rule 8**: Zero hardcoded secrets; dynamic `.env` loading with fail-fast empty fallbacks.
9. **Rule 9**: PR descriptions strictly start with `Close #<issue-number>`.

## 5. Independent Developer Validation Guide

Developers and reviewers can independently verify the sprint's technical progress across 5 tangible checkpoints:

1. **Checkpoint 1 (Wave 0 - Map Hygiene)**:
   - Run `cd apps/web && npm run dev` $\rightarrow$ open `http://localhost:3000`.
   - Confirm black dots (`NOT_IMAGE`/`NO_SIGNAL`) are hidden by default. Toggle `[Hiện camera mất tín hiệu]` and verify they reappear cleanly.
2. **Checkpoint 2 (Wave 1 - Active Crowdsource Flywheel)**:
   - Open any camera modal $\rightarrow$ click `[Báo cáo ngập tại đây]`.
   - Verify 30-second cooldown activates. Check Cloudflare R2 bucket (`warded-proofs/feedback/`) for the newly saved JPEG and companion JSON metadata with `trust: "unverified"`.
   - Dispatch repeated requests from the same IP $\rightarrow$ confirm HTTP 429 rate limit is enforced.
3. **Checkpoint 3 (Wave 2 - Autonomous Traffic Perception)**:
   - Start Go server $\rightarrow$ observe the map without clicking any camera.
   - The 50 Hot Set arterial cameras (Võ Văn Kiệt, Mai Chí Thọ, Điện Biên Phủ, Cộng Hòa) must automatically display Green / Yellow / Red colored markers updating every 60s.
   - Verify Gemini API dashboard: **Zero cloud VLM calls consumed for traffic**.
4. **Checkpoint 4 (Wave 2 - Rain-Triggered Flood Verification)**:
   - Simulate rainfall $\ge 0.10\text{mm/h}$ in the Go backend.
   - Verify background worker automatically checks priority flood chokepoints at $\le 2\text{ RPM}$ and updates flooded cameras to Blue badges without user clicks.
5. **Checkpoint 5 (Wave 3 - Labeling Toolchain)**:
   - Open `tools/eval/labeler.html`. Verify directional toggle (`Inbound`/`Outbound`), `[Dừng đèn đỏ]` checkbox, and motorcycle waterline depth radio buttons exist.
   - Run `python3 tools/eval/validate_labels.py` on exported labels and confirm exit code 0.
